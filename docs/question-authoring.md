# 問題集の作り方

アプリの問題はすべて `backend/src/main/resources/questions/<機能>/*.json` に置き、起動時に読み込んで出題する(実行時に AI で生成しない)。このドキュメントは、問題を追加するときの手順・形式・品質基準をまとめたもの。

## 1. 現在の問題数と目標

|---|---|---|---|---|---|
| 文法(TOEIC Part 5) | `grammar` | `g0001`〜 | 1000問 | 1000 | 1000 |
| 語彙(英検準1級 大問1・TOEIC) | `vocab` | `v0001`〜 | 1000問 | 1000 | 1000 |
| 読解 TOEIC Part 6 | `reading`(`toeic-part6`) | `r0001`〜 | 100セット | 100 | 100 |
| 読解 TOEIC Part 7 | `reading`(`toeic-part7`) | 〃 | 100セット(うち複数文書 39: 2文書 22、3文書 17) | 100 | 100 |
| 読解 英検 大問2(空所補充) | `reading`(`eiken-cloze`) | 〃 | 50セット | 50 | 50 |
| 読解 英検 大問3(内容一致) | `reading`(`eiken-long`) | 〃 | 44セット | 44 | 50 |
| リスニング | `listening` | `l0001`〜 | 620セット(TOEIC Part 2: 82、Part 3: 132、Part 4: 105、英検 Part 1: 106、Part 2: 92、Part 3: 103。2026-11-11 時点。書き直しは完了、追加の段階。残り 380) | 1000(難易度 1〜5 = 10/20/30/20/20%。1.1) | 1000 |

問題を追加したらこの表を更新する。ID は機能ごとの通し番号で、既存の最大値の次から振る(重複すると起動時にエラーになる)。

### 1.1 リスニングの難易度の分布と総数の目標(毎日の作業)

リスニングは形式ごとに、難易度 1〜5 を **10% / 20% / 30% / 20% / 20%** にし、総数を **1000 セット**(形式ごとの数は `scripts/questions/plan.js` の `TYPE_TOTALS`)にする。毎日の作業は次の2段階で進める。

1. **書き直し**:レベル1・2の余っているセットのうち、未解答(または解答の少ない)ものを、**新しい ID で**不足しているレベル(3〜5)に書き直し、元のセットは問題集から削除する。対象は `scripts/questions/listening-rewrite.json` に固定してある(146 セット)。同じ ID のまま中身を変えると、解答済みの扱いが残って出題されにくく、経験値も過去にさかのぼって変わるため、ID は必ず新しくする。場面・話題は元のセットを参考にしてよいが、台本・設問・解説・和訳はすべて新しいレベルの基準(4.2)で作り直す。
2. **追加**:書き直しが終わったら、形式ごと・レベルごとの不足に比例して、総数 1000 になるまで新しいセットを足す。

```bash
node scripts/questions/plan.js           # 形式ごとの現状・最終目標・書き直しの残り
node scripts/questions/plan.js today 8   # 今日の作業(書き直しの対象、または追加する形式とレベルの内訳)
```

- `DifficultyTests` は、形式ごとにレベル1を1割以上、レベル2・3を2割以上求める(リスニング以外はレベル1も2割以上)。書き直しでこれを割る日は、その形式の書き直しを後回しにする。
- すべてのリスニングのセットに `difficulty` を書いてある(2026-11-08 に推定値を書き込んで固定した)。追加・書き直しのセットにも **必ず書く**。省略すると推定(1〜3 の3等分)に回る。
- 書き直しの対象は `node scripts/questions/plan.js select <history.json>` で一度だけ選んだ(`history.json` はブラウザの localStorage `englishApp.history.listening` を保存したもの)。

## 2. 作業手順

1. **次の ID とファイル名を確認する**:各フォルダの最後のファイルを見て、続きの番号を使う。1ファイルの目安は、4択問題25問、セット問題10セット。リスニングで作る形式と難易度は `node scripts/questions/plan.js today` で決める(1.1)。
2. **問題を書く**:下の「3. 形式」に従う。**正解は必ず最初の選択肢(A)に書く**(書き間違いを防ぐため。記号は手順4で並べ替える)。
3. **構文チェック**:
   ```bash
   # リポジトリのルートで実行
   python scripts/questions/check.py backend/src/main/resources/questions/vocab/vocab-021.json
   ```
   値の後ろの余分なカンマ(`"…","}`)を自動修正し、JSON として読めるか・ID の範囲を表示する。
4. **正解記号を A〜D に均等にならす**:
   ```bash
   python scripts/questions/balance.py backend/src/main/resources/questions/vocab choice
   python scripts/questions/balance.py backend/src/main/resources/questions/reading set
   ```
   - `choice`:文法・語彙(4択の短文問題)、`set`:読解・リスニング(セット問題)
   - **3つ目の引数(ファイル名の glob)は新しく追加したファイルだけに一致させる**。`vocab-0[23][90].json` のような指定は既存の `vocab-020.json` にも一致し、既存問題の記号まで並べ替えてしまう(解答履歴の記号とずれる)。迷ったら1ファイルずつ指定する。
   - 正解以外の選択肢の並び順は保たれる。1問1行の JSON に整形される。
   - 解説に「A」「B」などの記号が書かれていると警告が出る。**解説では選択肢を記号ではなく語句で指す**(並べ替えると記号がずれるため)。「A を B に」のような構文説明の A・B は無視してよい。
5. **見直す**(「5. 品質チェック」)。問題が見つかった選択肢は、記号ではなく**語句を指定して差し替える**(並べ替え後は位置が変わるため)。
6. **テストして push**:`./scripts/push.sh "feat(vocab): 語彙問題を追加"`。形式チェックのテスト(`QuestionBanksTests` / `GrammarQuestionBankTests`)が CI でも実行される。

## 3. 形式

### 4択短文問題(文法・語彙)

```json
{"id":"v0001","point":"動詞","sentence":"The government decided to ------- the old law ...","choices":[{"label":"A","text":"repeal"},{"label":"B","text":"repel"},{"label":"C","text":"reveal"},{"label":"D","text":"revive"}],"answer":"A","explanation":"repeal は「(法律を)廃止する」。... repel は「追い払う」...","translation":"その法律は...廃止を決めた。"}
```

- `sentence`:空所は必ず `-------`(ハイフン7個)
- `point`:文法項目・品詞(例:`前置詞と接続詞`、`仮定法過去完了`、`形容詞(ビジネス)`)。弱点分析の分野分け(`QuestionTags`)にも使うので、既存の書き方(「時制(…)」「関係代名詞(…)」など)に揃える
- `difficulty`(省略可):1〜5。基準は「4. 難易度(レベル 1〜5)の定義」に従う。**語彙は必ず書く**(語の難しさは機械的に推定できないため。テストで検査)。文法・セット問題は省略すると、文の長さ・分野・設問タイプから形式ごとに 1〜3 の3等分で推定される(4・5 は推定されないので、必ず書く)
- `explanation`:なぜ正解か+他の選択肢がなぜ誤りかを日本語で
- `translation`:正解を入れた文の和訳

### セット問題(読解・リスニング)

```json
{"id":"r0001","type":"toeic-part6","title":"Email: Office relocation","passage":"...[1]...[2]...","script":null,"situation":null,"translation":"本文の和訳","questions":[
  {"question":"[1]","choices":["by","until","within","since"],"answer":"A","explanation":"..."}]}
```

| type | 内容 | 必須 | 設問 |
|---|---|---|---|
| `toeic-part6` | メール・告知など100〜150語。空所 `[1]`〜`[4]` | `passage` | 4問(うち1問は文挿入) |
| `toeic-part7` | 単一文書(メール・広告・記事・チャット等)1問あたり約84語(3問なら約252語)、または複数文書(2〜3文書。`【Document 1: E-mail】` のように見出しで区切る)。2文書は1問あたり約87語、3文書は1問あたり約106語(語数は passage を空白で数える。目標の95%〜115%に収める) | `passage` | 単一文書は2〜4問、複数文書は5問。文挿入問題は本文に `— [1] —`〜`— [4] —` を入れ、選択肢を `[1]`〜`[4]` にする |
| `eiken-cloze` | 英検 大問2。説明文250語前後、空所 `[1]`〜`[3]` | `passage` | 3問(選択肢は語句) |
| `eiken-long` | 英検 大問3。説明文400〜500語(テストで400〜550語を検査) | `passage` | 3〜4問 |
| `toeic-part2` | 応答問題(問いかけ+応答3つ) | `questions` のみ(`script` は null) | 5問(3択) |
| `toeic-part3` | 2人の会話 | `script` | 3問 |
| `toeic-part4` | 1人のアナウンス・説明 | `script` | 3問 |
| `eiken-part1` | 会話 | `script` | 1問 |
| `eiken-part2` | 説明文 | `script` | 2問 |
| `eiken-part3` | Real-Life(状況+放送) | `script`・`situation` | 1問 |

- 選択肢は文字列の配列で4つ(記号は付けない)。`answer` は `A`〜`D`。
- `passage` の空所番号は設問の数だけ必要(テストで検査)。
- **TOEIC Part 2**:`question` に問いかけ、`choices` に応答3つを書く。台本(`Narrator: Number 1.` → 問いかけ → `(A)`〜`(C)`)と男女の声の割り当ては `ListeningQuestionBank` が設問から組み立てるので、`balance.py` で並べ替えてもずれない。解答前の画面には文字を出さない。誤答は本番のひっかけ(同じ音・似た音の語、連想される語、疑問詞の質問に Yes/No で答える)に合わせ、正解が2つ取れないようにする。`translation` は null にし、和訳は解説に含める。
- **リスニングの `script`**:全行を `Man: ` / `Woman: ` / `Man 2: ` / `Woman 2: ` / `Narrator: ` のいずれかで始める(テストで検査)。TTS が話者名で声を選び、`Man 2` / `Woman 2` には別の声が付くので、TOEIC Part 3 の3人の会話に使う。台本は解答後にだけ画面に表示される。
- **TOEIC Part 3/4 の設問**:本番と同じく、詳細・推測の設問に加えて「What does the woman mean when she says, "..."?」形式の発言の意図を問う設問を入れる。Part 3 には3人の会話も混ぜる。
- **図表問題(TOEIC Part 3/4)**:セットに `graphic`(表・地図・グラフをテキストで表したもの。等幅フォントで表示される)を入れ、設問の1つを「Look at the graphic. ...」で始める。台本だけ、図表だけでは答えが決まらず、両方を組み合わせて初めて答えが出るように作る。「Look at the graphic」で始まる設問があるのに `graphic` が空だとテストで失敗する。

### ライティング

```json
{"id":"w0001","type":"opinion","topic":"Agree or disagree: ...","points":["Community","Costs","Elderly people","Mental health"],"passage":null}
{"id":"w0002","type":"summary","topic":"記事のタイトル","points":null,"passage":"200語前後の英文(3段落:現状・利点・問題点 が典型)"}
```

- `opinion`:英検準1級の意見論述。賛否両論ある社会問題。`points` は1〜2語で重複しない4つ。
- `summary`:要約問題。`passage` は160〜300語(テストで検査)。意見を含まない説明文。

### スピーキング(英検二次)

```json
{"id":"s0001","title":"A Community Garden","instruction":"You have one minute to prepare. ...","firstSentence":"One day, ...","scenes":["コマ1:...","コマ2:「That Saturday」...","コマ3:...","コマ4:..."],"narrationSample":"...","questions":[{"no":2,"question":"Please look at the fourth picture. If you were ..., what would you be thinking?","sampleAnswer":"..."},{"no":3,"question":"...","sampleAnswer":"..."},{"no":4,"question":"...","sampleAnswer":"..."}]}
```

- イラストの代わりに `scenes` で4コマの場面を日本語で説明する。2〜4コマ目には時間表現(「That evening」など)を入れる。
- `questions` は No.2(4コマ目の人物の気持ち)、No.3・No.4(社会的な話題への意見)の3つ。

## 4. 難易度(レベル 1〜5)の定義

問題の `difficulty` は次の5段階で付ける。学習者は TOEIC 700点台から始め、930点・英検準1級を目指すので、**レベル2が今の実力、レベル4が目標点、レベル5が目標を確実に超えるための上積み**になるように置く。迷ったら低いほうのレベルにする(難しく見せるために問題を不自然にしない)。

### 4.1 全体の基準

| レベル | 名前 | 目安の得点 | 解けると言えること |
|---|---|---|---|
| 1 | 基礎 | TOEIC 600点台 / 英検2級 | はっきり言われた1つの情報を、ほぼ同じ言葉で聞き取れる・読み取れる |
| 2 | 標準 | TOEIC 700点台(現在の実力) | 簡単な言い換えを見抜いて、1つの情報を取り出せる |
| 3 | 発展 | TOEIC 800点台前半 / 英検準1級の合格ライン手前 | 言い換えと、もっともらしい誤答(本文に出た語を使ったもの)を見分けられる |
| 4 | 難関 | TOEIC 880〜930点 / 英検準1級の合格ライン | 2か所以上の発言をつないで、または話し手の考えを推測して答えを出せる |
| 5 | 最難関 | TOEIC 930点超(L 475以上)/ 英検準1級の上位 | 訂正・撤回・却下された案を追い、最終的に有効な情報だけで答えを出せる |

難しさは**聞き取る・読み取る力**で決める。次の方法で難しくしてはいけない(どのレベルでも禁止)。

- **頭の中で計算させる**:足し算・引き算・割合・日数や金額の差など。数字が出てきてもよいが、答えは本文で言われた値そのものにする(「何日遅れが増えたか」「合計はいくらか」は不可)。計算は聞き取りとは別の力なので、正答率がリスニング力を表さなくなる。
- **本文にない知識・常識で答えさせる**。
- **正解の根拠を本文に書かない**:推測問題でも、根拠になる発言(理由を表す `so` / `since` / `because`、直後に続く説明など)が本文に必ずある。解説には根拠の英文を「」で引用する。引用できない設問は作らない。
- **選択肢の見た目で答えが分かる**:正解だけが長い・詳しい・本文の語をそのまま使う、などの偏りを作らない。4つの選択肢は長さと書き方をそろえる。

### 4.2 リスニング(TOEIC Part 3・4、英検 Part 1〜3)

| 観点 | 1 基礎 | 2 標準 | 3 発展 | 4 難関 | 5 最難関 |
|---|---|---|---|---|---|
| 正解と本文の関係 | 本文と同じ語 | 簡単な言い換え(`dispatched` ← `left the warehouse`) | 言い換えが必須 | まとめた言い換え(複数の発言を一言で表す) | まとめた言い換え+最終的に有効な情報の選び出し |
| 答えの場所 | 1か所、はっきり言われる | 1か所 | 1か所+近くに誤答の根拠 | 2か所以上をつなぐ | 訂正・撤回・却下の後の情報 |
| 設問タイプ | 詳細のみ | 詳細が中心、推測は0〜1問 | 推測・発言の意図を1問 | 推測・発言の意図・理由を2問以上 | 3問とも推測・意図・理由・訂正の追跡 |
| 誤答 | 本文に出ない内容 | 本文に出た語を1つ使う | 本文に出た語・場面を使う | 本文で一度出たが否定された内容 | 却下された案・撤回された予定・別の人の発言 |
| 台本(Part 3 の目安) | 6行・80〜100語 | 6〜7行・100〜120語 | 7行・110〜130語 | 8行・120〜150語 | 8〜9行・140〜170語 |
| 話の流れ | 予定や依頼が1つ | 問題と解決が1つ | 問題+案が2つ | 案の比較・反対意見 | 案の却下・情報の訂正・方針の変更 |

- 語彙・話の速さで難しくしない(TTS の速さは一定)。難しさは「どこを聞けば答えが決まるか」の複雑さで出す。
- レベル5でも、根拠の発言そのものは聞き取れる英語にする(早口・言いよどみ・聞き取れない固有名詞に頼らない)。
- 例:l0343(レベル4。「though」と「They said that last week too」をつないで、約束が守られないと推測する)、l0345・l0346(レベル5。却下された案・訂正された報告から、最終的に有効な情報を選ぶ)。

### 4.3 読解(TOEIC Part 6・7、英検 大問2・3)

| レベル | 基準 |
|---|---|
| 1 | 答えは1文の中にあり、選択肢は本文の語をそのまま使う |
| 2 | 答えは1文の中にあり、簡単な言い換えが必要 |
| 3 | 段落の中の2文をつなぐ。NOT 問題・文挿入問題はこのレベルから |
| 4 | 段落をまたぐ、または複数文書(2文書)をつなぐ。筆者の意図・推測 |
| 5 | 3文書をつなぐ、または訂正・条件・例外(`unless` / `except`)を踏まえた最終的な情報を選ぶ |

### 4.4 文法(TOEIC Part 5)・語彙(英検 大問1)

| レベル | 文法 | 語彙 |
|---|---|---|
| 1 | 品詞・基本的な時制・前置詞 | TOEIC 600点の語(`schedule`、`deliver`) |
| 2 | 関係詞・受動態・接続詞と前置詞の区別 | TOEIC 700〜800点のビジネス語(`postpone`、`reimburse`) |
| 3 | 分詞構文・仮定法・紛らわしい語形(`economic / economical`) | TOEIC 900点の語・英検準1級の頻出語(`stipulate`、`alleviate`) |
| 4 | 倒置・仮定法の倒置・群前置詞・高度な接続表現(`provided that`、`lest`) | 英検準1級の難語(`exacerbate`、`relinquish`) |
| 5 | 文全体の構造を見ないと決まらない問題(離れた主語と動詞の一致、省略・倒置の組み合わせ) | 英検準1級の上位語・語法の区別が必要な語(`acquiesce in`、`impinge on`) |

文法・語彙も、選択肢の中に正解が2つ取れるものを作って難しくしてはいけない(「5. 品質チェック」)。

### 4.5 その他の目安

- 目標は TOEIC 930点・英検準1級。学習者は現在 TOEIC 700点台。
- 文法:TOEIC 600〜800点レベルを土台に、900点レベル(倒置、仮定法の倒置、群前置詞、`economic / economical` のような紛らわしい語形)を3〜4割入れる。
- 語彙:英検準1級の大問1に近い語(`exacerbate`、`relinquish` など)を中心に、句動詞と TOEIC のビジネス語彙を混ぜる。易しすぎる語ばかりにしない。
- 読解・リスニング:話題はビジネス(TOEIC)と社会問題・科学(英検)を偏りなく。
- **英検の話題(`theme`)**:英検 大問2・3(`eiken-cloze` / `eiken-long`)、リスニング Part 2(`eiken-part2`)、ライティング(`opinion` / `summary`)には `theme` を必ず書く。値は `社会・政治` / `環境・エネルギー` / `科学・技術` / `医療・健康` / `教育・心理` / `ビジネス・経済` / `文化・歴史・生活` のいずれか(`Themes`)。長文・説明文とライティングのそれぞれで、どの話題も 7〜30% に収まっているかを `ThemeBalanceTests` が検査する。追加前に現在の分布(テストの出力)を見て、少ない話題から作る(2026年11月時点で少ないのは、長文・説明文の「社会・政治」、ライティングの「文化・歴史・生活」)

## 5. 品質チェック(必ず見直す)

作成後に全問を読み直し、次の問題がないか確認する。今までの作成で実際に見つかった例を挙げる。

| よくある問題 | 例 | 直し方 |
|---|---|---|
| **正解が2つ取れる** | `strictly prohibited` と `strictly forbidden`、`postponed until` と `delayed until`、`respond to` と `reply to` | 誤答を、文法的・意味的に明確に誤りの語に替える |
| 誤答の語が名詞としても成り立つ | `Working in ...` に対する誤答 `Work in ...` | 冠詞が必要な可算名詞などに替える |
| 英文が不自然 | `keep on your seat belts`、`check with either` | 例文を書き直す |
| 解説・正解記号の書き損じ | 正解が A なのに `answer` が D | 正解を最初の選択肢に書くルールを守る |
| 品詞ラベルの誤り | 副詞なのに `point` が「形容詞」 | 修正する |
| JSON の構文エラー | `"text":"word","}` | `check.py` が自動修正する |
| 正解語の重複 | 同じ単語が別の問題でも正解 | 多少は可。多い場合は別の語に替える |
| **既存問題との重複** | 既存と同じ英文、同じお題、同じ会社名・場面の読解文(例:同じ「Solaris Energy の受賞記事」) | 作成前に既存の題名・お題・正解語を一覧で確認する。英文・お題・読解の題名の完全一致はテストで検出される。題名を言い換えただけの同じ話題(例:英検リスニング Part 2 の「Coral reef restoration」と「Restoring coral reefs」)も、本文の語の重なりで `DuplicateSetTests` が検出する(英検 Part 2 は 0.4、その他は 0.55 以上で失敗) |
| **頭の中で計算させる** | 「合計はいくらか」(1人 $36 × 100人 + 15% + $900)、「遅れは何日増えたか」(1週間 → 2週間) | 本文で言われた値をそのまま答えにする設問に替える。計算が前提の台本は作り直す(4.1) |
| **正解の根拠が本文にない** | 「なぜ正午までに連絡するのか」に、本文は「今日中に経路を確定する」としか言っていない | 根拠の発言(`so` / `since` / `before then` など)を台本に入れる。解説に根拠の英文を引用できるか確かめる |
| **正解だけ長い・詳しい** | 4つのうち正解だけが2倍の長さ | 4つの長さと書き方をそろえる |
| **難易度が低すぎる** | 語彙の正解が `change`・`popular`・`contact` などの基本語 | 語彙は英検準1級(`exacerbate`・`acquiesce` など)と TOEIC 900点のビジネス語(`collateral`・`stipulate` など)を中心にする。文法は追加分の3〜4割を倒置・仮定法・紛らわしい語形・高度な接続表現(`provided that`・`lest`・`notwithstanding` など)にする |
